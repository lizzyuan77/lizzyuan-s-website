Does One Year of Income Mislead Us About Mobility?

A SQL-in-Python tutorial: match parents and children, average their incomes, and compare the estimates.

Does averaging several income observations change how strongly parents’ income predicts their children’s earnings? In this tutorial, you’ll use SQL inside Python to link two generations and compare single-year and three-observation intergenerational elasticities (IGEs).

The IGE is the slope in:

\[\log(\text{child income})=\alpha+\beta\log(\text{parent income})+\varepsilon\]

A slope of 0.4 means 10% higher parental income is associated with roughly 4% higher child income. It measures relative persistence, not a causal effect or the chance of out-earning your parents.

1. Prepare the tables

You need basic Python, pandas, NumPy, and SQL. Obtain a PSID Data Center extract and Parent Identification File; the README provides the variable list and download steps. Run 01_import.py to create SQLite tables for people, parent links, yearly family membership, family income, and CPI.

import sqlite3
import numpy as np
import pandas as pd
con = sqlite3.connect("data/working/blog6.sqlite")

Keep both permanent identifiers, id68 and pn. Yearly family_id must be paired with wave; it does not identify the same family across interviews.

2. Match children to mothers

query = """
SELECT c.id68 AS child_id68, c.pn AS child_pn, c.sex, c.weight,
       p.id68 AS parent_id68, p.pn AS parent_pn
FROM people AS c
JOIN parent_links AS l
  ON c.id68 = l.child_id68 AND c.pn = l.child_pn
 AND l.parent_type = 'birth_mother'
JOIN people AS p
  ON p.id68 = l.parent_id68 AND p.pn = l.parent_pn
WHERE c.birth_year BETWEEN 1970 AND 1974
  AND c.sex IS NOT NULL
"""
pairs = pd.read_sql_query(query, con)

SELECT chooses columns; aliases distinguish child from mother. JOIN ... ON matches both identifier parts. WHERE selects the birth cohort. The complete script saves this result as pairs; a LEFT JOIN audit counts unmatched children. 1,771 children match to a mother.

3. Attach income by year

Join each child’s membership to the mother’s membership on the same wave and family_id. Require both to be current members. Then join family income on those same keys. The executable query is in 02_match.sql.

Parental resources are family income in 1980–1982, reported in interviews 1981–1983. Adult earnings are from 2010, 2012, and 2014, reported the following years. These adult observations span five calendar years, not three consecutive years.

Convert each amount to 2020 dollars before averaging, using CPI for the income year:

f.total_income * (SELECT cpi FROM cpi WHERE year = 2020) / k.cpi

Adult earnings are selected by household role, not sex. However, this extract combines reference-person total labor income with spouse income excluding farm/business income. These are not harmonized earnings measures. The gender and age comparisons illustrate the workflow; substantive comparisons require consistent coverage and re-estimation.

4. Average before joining generations

SELECT child_id68, child_pn,
       AVG(real_income) AS parent_mean,
       MAX(CASE WHEN income_year = 1981
                THEN real_income END) AS parent_single
FROM parent_history
WHERE income_year IN (1980, 1981, 1982)
GROUP BY child_id68, child_pn
HAVING COUNT(*) = 3 AND COUNT(real_income) = 3;

GROUP BY collects each child’s observations; AVG calculates their mean. MAX(CASE ...) extracts 1981. HAVING requires three nonmissing observations, after checking year-key uniqueness.

Repeat for adult earnings, selecting 2012 as the single year. Join the summaries afterward: joining three parent years directly to three child years produces nine rows per child.

5. Compare weighted slopes

Keep the same children in both models, with positive final income measures and positive 2015 individual longitudinal weights. Average real amounts, including genuine zeros, before taking logs; report exclusions. The retained sample has 237 daughters and 196 sons.

def fit_ige(d, child_col, parent_col):
    x, y = np.log(d[parent_col]), np.log(d[child_col])
    w = d["weight"]
    xm, ym = np.average(x, weights=w), np.average(y, weights=w)
    return np.sum(w*(x-xm)*(y-ym)) / np.sum(w*(x-xm)**2)

The pooled estimate changes from 0.35 to 0.37. Daughters’ estimate rises; sons’ falls. All three bootstrap intervals for these changes include zero. Averaging does not establish a difference here.

Why average? Under classical measurement error, temporary noise in parental income attenuates the slope. Averaging can reduce that noise, but does not guarantee a higher estimate or recover lifetime income.

6. Check measurement age

Holding parental income and weights fixed, sons’ point estimate is 0.40 at average age 28 and 0.71 at 42. Daughters’ estimates are 0.42 and 0.39. This illustrates measurement-age sensitivity, not life-cycle bias alone: calendar conditions, earnings coverage, and sample selection also differ or matter. The separate averaged age-window change for sons has an interval including zero.

Takeaway

Here, averaging changes the pooled IGE only slightly. The practical lesson is to match identifiers carefully, aggregate before joining, and compare identical samples. Neither these estimates nor the gender difference establishes a broad mobility claim: the averaged daughter–son difference’s interval (-0.67 to 0.03) includes zero.
